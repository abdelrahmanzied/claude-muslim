# Muslim pane — design

The Muslim pane's visual means and layout, following [DESIGN.md](../../../DESIGN.md). Behavior is in [muslim-pane.md](muslim-pane.md).

## Visual means

A Pane (`$.ui.open({ id: 'muslim', title: '☾ Muslim' })`) docked beside the «القرآن الكريم» pane, drawn by one Client (`client.tsx`) as an Svg holding HTML and CSS in a foreignObject, the same approach as the Quran pane (the API has no HTML or native card element, so a drawn picture is the only way to match the Desktop's own session-panel cards: rounded bordered cards, a header with a chevron and a value, icon rows, a switch). `view.ts` builds the picture, `layout.ts` holds the fixed pixel layout and the hit testing, `model.ts` the pure data. Colors stay in `view.ts`: dark by default, light under the app's color scheme or the Claude theme row when it names light or dark, and the accent from `src/shared/color/` (the plugin-wide `/muslim color`, orange by default) for the next prayer, the next row, the switch, the progress bars and the play button. Fonts use the shared embedded Tajawal face described below; Arabic is left exactly as authored on desktop.

**Why a drawn picture:** the same reason as the Quran pane. **Fallback:** the terminal gets a plain text reply from `/muslim pane` and a text body if the pane is placed there; Arabic goes through `src/shared/arabic`.

## Background and font

The pane draws no fill of its own: the root and the cards are `background:transparent` in both themes, so Claude Desktop's panel shows through exactly as in the Quran pane; the cards keep only their 1px border line and rounded corners (the next-prayer row uses a transparent text overlay; only the play button, progress fills and enabled switches have solid accent fills). The type is Tajawal 400 and 700 for Arabic, Latin and numbers alike, embedded through `src/shared/font/` (shared with the Quran pane; weight 500 resolves to 400). All text uses the fixed type scale in Layout below, without `.ar` font scaling; daily and settings cards share the same title size. Fixed heights and hit boxes stay aligned, with text centered by CSS. Prayer names and times, Athan, Quran metadata, the Athkar off note, and settings face/pill text use line-height 1 and a .12em downward shift to center Tajawal beside icons. The previous typography is preserved in git at `126e2bd`.

## Title row and folding

Each card's title row is: a 20px icon in the main color, the feature's standard icon from DESIGN.md §3 Icons and `src/shared/icon/`, the same one its settings tab shows (`sujoodreal` for prayers, `qpane` for the Quran, `horizon` for the athkar in both periods), the title, then at the far end the muted meta (the title and meta use line-height 1 and drop .12em, the Quran pane's fix for Tajawal sitting high, so the text centers on the icon) (quarter, `٢٢ / ٢٢`; the prayer header has no meta) and a fold control. Pressing anywhere on the row (a pointer cell overlapping it counts, via the half-cell slack) folds the card to just its row and unfolds it again; the chevron points down when open and left (RTL) when folded. Folded cards are 56px tall and the cards below move up; heights and hit boxes come from `cardRects(folds)` in `layout.ts`, and a folded card's inner targets are not hit. The folded state is kept in `$.state` (`muslim.paneFolds`), so it survives redraws and reloads in the session.

## Light and dark

One token set per theme, switched exactly as in the Quran pane: dark by default, light under `prefers-color-scheme: light`. Claude Code's own `theme` row is not read (it can differ from the Desktop's, which made light mode draw with dark tokens). Elements take colors only from `VARS` in `view.ts`; raw hex and RGBA values stay in the palette CSS. There are no `--raised`, `--raised-2` or card-face fill tokens. The host remains visible through cards and controls.

| Token | Dark | Light |
| --- | --- | --- |
| `--text` / `--text-2` | `#eeede8` / `#c6c3bb` | `#292824` / `#514e47` |
| `--muted` / `--dim` | `#a6a299` / `#969289` | `#736f66` / `#817c72` |
| `--line` | `rgba(238,237,232,.13)` | `rgba(41,40,36,.14)` |
| `--line-soft` | `rgba(238,237,232,.07)` | `rgba(41,40,36,.07)` |
| `--hover` | `rgba(238,237,232,.04)` | `rgba(41,40,36,.04)` |
| `--active` | `rgba(238,237,232,.07)` | `rgba(41,40,36,.07)` |
| `--on` (switch thumb) | `#faf9f5` | `#ffffff` |
| `--on-accent` (play glyph) | `#1f1e1d` | `#ffffff` |

Secondary actions («✓ أتممتُها») are transparent with a 1px `--line` hairline and 10px radius; inset shadows draw the hairline without changing the content box. The tertiary **Open** action is transparent, with no border. The previous/next circles are transparent with a 1px `--line` ring, like the Quran pane's controls. Settings pills and value buttons use the same transparent hairline treatment. The LTR `/muslim terminal-arabic` copy chip and the city command sheet are outlined, with no solid fill. Existing fonts, sizes, heights and press rectangles stay fixed.

Hover uses `--hover`, a 4% overlay of the mode's text, including the next-prayer row. Active settings pills and chosen method rows use `--active`, 7%, with neutral text; the selected tab instead uses bold text and a 2px text-color underline over the strip's 1px bottom line. Accent is reserved for play, the next prayer, progress fills, enabled switches and color dots; card-title icons retain their existing accent pending approval of neutral icons. Copy confirmation is neutral. No keyboard focus ring is drawn today, so this change adds none.

## Footer chip

On Desktop the footer's SessionMode row gets one plain Button, `☾ Muslim`, owned by this feature (its own `ui.render` hook, registered before Quran's so it is leftmost), followed by the prayer text and engine items (Quran adds no footer item). The label has a matching Text child and the button opens the Muslim pane when closed and closes it when open. It stays at every width. The SessionMode slot is the only footer space the API gives plugins and Desktop sets its width, so every item there stays short. Not drawn in the terminal.

## Layout

A heading row, then three daily cards and one settings card stacked in one right-to-left column. The heading (`TOP_Y` 0, `TOP_H` 36px; the full avatar fills its height. The Desktop adds its own space above the picture and the API has no setting for it, so the heading starts at the picture's top edge; the 12px bottom margin is tuned against that space live): the full Muslim avatar, 36px tall and approximately 38.4px wide (`avatar.ts`, the base sprite with nothing in its hands, pixelated, no background) and «مُسلِم» at 24px bold with a 10px gap at the right edge, 20px in; the LTR `/muslim` label at 12px dim at the left edge, 20px in, never hidden. Both «مُسلِم» and `/muslim` are vertically centered on the avatar row. It has no hit target. The cards start at `CARDS_TOP` (44px), 12px outside margin (`PAD` in `layout.ts`) and 12px between cards, 12px corner radius (the Claude Desktop side cards' radius; the next-prayer row inside uses 8px), 1px line border, 16px side padding, 28px header. Every height is a constant (the pane is CARDS_TOP + prayer + GAP + Quran + GAP + athkar + GAP + settings + PAD tall, see `layout.ts`), so the hooks module hit-tests clicks against the same numbers the Client draws with, whatever the data.

Scrolling moves the host's body window over this fixed picture only when there is actual overflow. A person-origin Desktop `ui.scroll` whose clamped offset equals the last rendered offset is consumed without drawing, including wheel/trackpad input over the passive reciter and surah labels and ticks at either edge. `UiScrollInput` has no surface field, so the hook remembers the pane's surface and offset from `ui.render`; it does not infer them from the session. Plugin-origin requests and the terminal text body pass through. The Client has no size polling: `ClientSurface` already calls it on resize, and polling a flickering measured row count only caused redundant `setState` picture swaps for size messages nobody used. Fixed SVG/card heights and the existing pointer mapping stay the same.

- **Prayer** — header «الصلاة» and fold chevron, with no city in the title row. The next block: «الصلاة القادمة», the name at 20px bold in the main color; at the left the time at 20px and the countdown below. Five 32px rows: icon, name, time at the end; done rows dim with a check ring, the next row on the 4% text overlay with its name and dotted ring in the main color, upcoming rows a ring. A divider, then the 40px Athan row: bell, «الأذان», switch at the left end. Below it, a passive centered 12px muted line with line-height 1 reads «مواقيت <city>», escaping the city exactly as stored inside `<bdi>` so Arabic and Latin names keep their direction. `CITY_TOP = ATHAN_TOP + ATHAN_H + 4` (328px) and `CITY_H = 16`; `PRAYER_H = CITY_TOP + CITY_H + 12` (356px), leaving 12px below the line. The open height stays fixed even without a city, when the line is absent. Folding hides the line and keeps the 56px title row. No new hit target; `cardRects` shifts all later cards and targets down by the new height.
- **Quran** — header «القرآن», with the segment label at the left only when folded. Hero (top 52, height 76): the status line (12px; «يتلى الآن» in `--accent` when playing), then the surah title button «سورة X ▾» (20px bold, top 88, 32 tall); the Quran avatar at the left, 96×90, drawn by the Quran feature and passed as an SVG string through the panel signal. Split recordings add the «ابدأ من» line at top 128 (right 16, left 120, 28 tall: small label, segment label, chevron). The reciter row (microphone, name, chevron; 28 tall) sits at 134 + off, the 5px bar at 170 + off, the times row at 182 + off (LTR grid 48px 1fr 48px: elapsed, quiet «الوقت تقريبي», total), and the controls row at 216 + off: repeat-segment (16px radius, caption «المقطع»), previous (20), play/stop (26, `--accent`), next (20), repeat-surah (16, caption «السورة»); the spacing scales down on narrow panes. `off` is 30 for a split surah and 14 for a whole one, so the card is 316 or 300 tall. The picker is a sheet over the card (`--sheet` background, `--sheet-line` border, shadow; 432 tall; the card grows to 474 + off): a head with the list's icon, title («اختر القارئ», «اختر السورة», «ابدأ من») and a «رجوع» button, a 38px search box, eight 34px rows (the lit row is the one under the pointer, else the keyboard highlight; surah rows keep their number in a separate column, never «·»), an 18px drag scrollbar when there are more than eight rows, and a footer with `n / N` in Arabic digits and the LTR hint `Use ↑ ↓ for scrolling`. No wheel scrolling. Only the sheet is interactive while it is open. Hit boxes in `layout.ts` use the same constants as the view.
- **Athkar** — header with the period's title and `٤ / ١٢`, then one 36px row: the `horizon` icon, the bar, an 84px ✓ **أتممتُها** button beside the 56px **Open** button at the left end. Finish is present and hit-testable only for an available unfinished period; its space returns to the bar when done. Both buttons use centered 14px text, 10px horizontal inner padding and an 8px gap, with a transparent hairline finish button and text-only Open action, both using the 4% hover overlay. Confirmation fills every count through the owning feature's `athkar-finish` action, producing a full fraction and bar and the visible current-period band's existing finale. It neither opens nor unhides a band. Header folding and card height stay unchanged.

### Type scale

| Size | Role |
| --- | --- |
| 24px | Plugin heading «مُسلِم», the largest text in the pane |
| 20px | Next prayer name and time; stepper glyphs |
| 16px | All daily and settings card titles |
| 14px | Body rows, Athan, buttons, settings labels and values |
| 12px | Header values, prayer city bottom line, next-prayer label, countdown, bar times, `/muslim`, notes, hints and settings secondary text |

The only exception is settings tab labels at 11px. At the 240px minimum width each tab is 31.6px wide, with 27.6px left after horizontal padding. Offline shaping of the embedded Tajawal gives «الأذكار» a width of 28.572px at 12px, so it does not fit; at 11px it is 26.191px and stays on one line. All font sizes are explicit pixels; there is no em-based font scaling.

## States

- Hover lights a control or button with `--hover` (4% text overlay; the play button brightens); active setting choices use `--active` (7%). The pointer is whole cells on Desktop, so a target counts as hit when the cell overlaps it, the nearest one winning, as in the Quran pane.
- Inactive controls (no Quran catalog yet, first or last surah, segment repeat or «ابدأ من» on a whole surah, no city, athkar off) are dimmed and not hit.
- No scores or streaks: the athkar fraction is the person's own count, shown only to them.

## Full-player navigation

The Quran player lives in the card; there is no button that opens the Quran pane (the standalone Quran pane and `/quran` still exist). Picks and repeat buttons go through the panel signal, so Muslim never imports Quran; Quran reconnects during the Muslim pane render and input chain. The scrollbar drag follows the Quran pane: the Client posts drag messages while a drag is in progress and the row scale is frozen at the press.

## Settings — approved layout “a” and icon picks

The main-color choices are small 16px dots centered in their press areas, not stretched to the area's shape; the chosen one gets a thin ring around it, with no check mark.

One folded «الإعدادات» card follows athkar. Its 56px header uses the existing card shell, Tajawal, **ترس بأسنان** (`gearteeth`) in the shared accent, the muted «٤ أقسام» count and fold chevron. The separate **عام** tab uses **منزلقات** (`sliders`). State is separate from the three daily folds.

The user approved layout “a” (`strip()` / `.tabs.a` / `.tab`) from the icons-avatars design: one horizontal, non-scrolling RTL row of four equal columns, each with a 20px icon above an 11px label. Order and exact approved icon picks:

| RTL position | Label | Approved icon name | Catalog id |
| --- | --- | --- | --- |
| 1 (rightmost) | عام | منزلقات | `sliders` |
| 2 | الصلاة | سجود واقعي | `sujoodreal` |
| 3 | الأذكار | شروق وغروب | `horizon` |
| 4 (leftmost) | الذكر | حبّات Spinner | `spinbeads` |

All six chosen SVG fragments (including `gearteeth`) are copied verbatim from the approved catalog. `qpane` is the Quran pane’s mushaf silhouette fitted to 24px; Every card header uses its feature's tab icon (DESIGN.md §3 Icons): `sujoodreal`, `qpane`, `horizon`. The الذكر label is exactly «الذكر»; the first row’s Arabic description explains that it controls the thikr shown in Claude Code’s **Spinner** (the working line), with Spinner and Claude Code in English.

The accordion was replaced to eliminate category-row scrolling and reach any category in one tap. A transparent strip with a 1px `--line` bottom edge holds muted tabs; the selected tab uses `--text`, bold weight and a 2px underline in `--text`, with no raised box or accent tint. General is selected on first open, and one category is always selected while open. Repressing the selected tab does nothing, preserving its face/page; switching tabs resets to main/page 0. Sub-faces and «رجوع» remain beneath the strip.

Geometry: `widthOf` clamps the picture to 240–1200px (8.4px per reported column, 360px fallback). Cards have 12px outer insets. The strip has 16px card insets, a 1px border box (transparent on three sides, `--line` at the bottom), 4px padding and 4px gaps. Keeping that border box preserves every tab rectangle; the underline is absolutely drawn down to the bottom edge without changing layout. At 240px, the card is 216px, the strip 184px and each tab 31.6px wide. Strip height is fixed at 60px; tab height is 50px: 4px padding, a 20px icon, 4px gap and one 14px label line (the 38px stack is centered vertically in the tab; the 60px strip height is kept). Padding is 4px. Labels stay on one line using the 11px exception documented in Type scale above. The Client never measures labels. The body starts at card y=132 (56px header + 60px strip + 16px gap). There is no settings-body subheader; the first row starts here.

The non-null selected category lives in `paneSettings`. `isSettings` rejects null categories. `loadSettings` safely maps valid legacy null-category accordion state to general/main/page 0, preserving open/closed state, without a render-time write. Invalid saved data falls back to folded general. The next input naturally saves normalized state.

Every settings row begins with its Arabic label at RTL start (the right), followed by a short Arabic description at 12px in `--muted`. Latin product names stay Latin and command buttons are LTR. The label line is 22px tall; the description starts at y+26 (4px gap), has 16px line-height, and choices start at y+52 (10px below the description). Switches instead occupy a 38×22px target at the left end of the label line, with the existing 38×22px drawing and 150ms thumb transition. The color dots sit on the label line at the far (left) end, like the switches, and stay 16px; the row is a 70px inline row. All other controls stay on their own line at 28px high, including at widths below 360px. Row heights include `ROW_GAP` = 28px between a row's last shown line and the next row's label, the same in every tab: switches 70px, choices 108px, rows with a shown extra stepper line 146px. The pane has no end-of-turn switch: that line is terminal-only. The optional Before-minutes and Seconds steppers count toward their row's height only while shown: «عرض الصلاة» set to «دائمًا» or «إيقاف», and «السرعة» set to «تلقائي», are 108px, so the next row follows after the normal 28px. The extra control line begins at y+90. Every height stays a constant (nothing is measured); drawing and `settingsBody` targets use the same row `y`. A tab's body height is one constant: the sum of its rows with the stepper line counted (the tallest case), minus the last row's gap, plus an 18px end space (`BODY_END`). Adjustment rows use the same label, description and separate controls geometry (108px each). The athkar tab is its two rows only; the earlier preview box was removed (a static picture that did nothing). Demo notes and controls are omitted, and religious samples retain their authored words and tashkeel handling.

`settings.ts` owns the category/body constants, pure row data, control effects and control rectangles; both SVG drawing and `layout.ts` hit testing consume `settingsBody`. Main body heights: prayer 530px, athkar 168px, thikr 314px, general 238px; prayer and thikr drop to 492px and 276px while their stepper line is hidden (`mainHeight(category, options)`), so the card never leaves a blank where a hidden row was. Detail heights: methods 548px, adjustments 740px, city 310px. The open card is `132 + selected-body + 12`; folded it is 56. Each tab rectangle follows the same nearest-edge / half-cell slack arbitration as the controls. Tab and body targets disappear when folded, while the independent fold header can reopen the card; only the selected body has targets. The surrounding host scrolls the resulting fixed picture with the existing no-movement redraw suppression unchanged.

Long lists are paged, six 70px slots per page, retaining all 20 methods. The last page keeps the same six slots and body height; paging controls are disabled at the ends. No inner HTML scroll and no measured list height. Lists and steppers have a «رجوع» row. All method hints, adjustment descriptions, empty-list hints and detail notes are Arabic. City invokes the existing Salah question directly from the press context and keeps its Arabic command sheet with Copy. Terminal Arabic has no detail face: beneath «العربية في Terminal» and «لكل ترمينال: شغّل هذا الأمر في الترمينال», one LTR `/muslim terminal-arabic` button (no glyph) copies the command directly using the `copy` effect (`$.ui.copy`; show the command in a toast on failure). After a press that copied (`isCopied`), the button shows «تم النسخ ✓» in the text color (`var(--text)`, class `copied`) for 2 seconds (`COPIED_MS`), then returns to the command text; a failed copy keeps the toast and never shows «تم النسخ». The transient is `$.state` `muslim.paneCopied` = `{ command, until }` (`until` = copy time + 2000, epoch ms). The model carries it as `settings.copied` only while `until` is later than the clock, so a stale entry never draws; `$.clock.after(2000)` clears the entry (only if it is still this press's) and invalidates to redraw. The city page's «نسخ الأمر» button confirms the same way. Old saved terminal-face state normalizes to general/main/page 0 on read.

Settings switches render from session `muslim.paneOptimistic` over the normalized options. A press writes the requested boolean to that small partial map before `$.config.set`; `$.state.get` during drawing subscribes the pane, so it redraws while the config write is pending. A denial removes the entry using the write’s returned version, so it cannot roll back a newer press. On reload the existing `session.start` hook removes entries whose values now equal the options. No state writes happen during drawing. This changes settings feedback only; the daily cards still read their owning features. Values for other settings come from normalized options and Quran’s read-only feed, without a competing store.

The terminal gets all settings and their commands in tab order, عام first and the exact heading الذكر, through the existing Arabic `show` path. Native Desktop painting and scroll feel still require a live host check; engine tests prove geometry, input routing, state and API calls.

In light mode only, the pixel-art header avatar carries `filter: drop-shadow(0 1px 1.5px rgba(31,30,29,.35))` (light media query and `.theme-light`; `.theme-dark` sets `filter:none`) so it stands out on the light card; dark mode and the art are unchanged.
